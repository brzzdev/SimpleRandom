# Test targets are chosen by risk, not by symmetry

Tests exist to protect the domain rules — deck arithmetic, pooled draws, cascade behaviour, sync policy. Regression cover under an untagged `main` (ADR-0001) is a welcome side-effect, not a goal. **"The app is a TCA 2 showcase, so its tests should be too" is explicitly rejected as a driver**: writing tests to demonstrate a library produces uniform, low-value coverage that breaks on every refactor and catches nothing.

Four test targets: `DatabaseTests`, `RandomiseFeatureTests`, `ListsFeatureTests`, `CombineFeatureTests`. This reverses an earlier one-per-feature-target line, which was symmetry written before there was a reason — `ModelsTests` would assert `@Table` declarations that hold no behaviour, and `AppFeatureTests` would assert that `TabView` works.

`DatabaseTests` is the addition and the one nothing else can replace: ADR-0002's constraints are enforced by `SyncEngine` **at runtime**, so the schema itself needs assertions. `Delete All Lists` rides there as a cascade case rather than justifying a target for a `Form`.

## How the tests are built

- **A fresh in-memory database per test**, from a suite-level dependency trait whose scope is provided per test case. Always the real `migrator` — a hand-written test schema would forfeit the entire reason `DatabaseTests` exists.
- **Seeded inline, no shared fixture.** These tests need small specific worlds — a three-item List with two already drawn, a Combo over two Lists where one is empty — and those do not share a seed. A fixture also makes tests read as assertions about `seedSampleData()` rather than about the domain.
- **Exhaustive `TestStore`.** Non-exhaustive mode earns its keep on deep trees and long integration flows; this app is depth-one or two with tiny state, so it would be buying a discount on a cost we are not paying — and exhaustivity is what makes library churn fail loudly.
- **Determinism from our own seeded generator.** Every Point-Free doc comment writes `LCRNG(seed: 0)`, but `LCRNG` is a `private struct` inside swift-dependencies' own test file. Ten lines, written locally, shared with nothing.
- **Assertions on domain properties, not literal picks.** Deck: draw N times, assert the multiset of results *is* the pool and that exhaustion lands on N+1. A literal-pick expectation is not reasoned to, it is discovered by running the test and pasting the output — a snapshot in disguise, pinned to the standard library's rejection sampling, which is not a contract.
- **`assertQuery` is rejected.** Its expectation is generated by running the code, so a cascade test written that way records what the schema *did*, not what the rules say it must do: a wrong `ON DELETE` goes green on re-record. Recorded as an escape hatch if cascade assertions across six tables get unwieldy.
- **Image snapshots are scoped** — a named state list on one pinned simulator, each in light and dark (ADR-0005), plus the result sheet alone at accessibility XXXL to hold ADR-0018's "scales rather than truncates" claim honest. Deliberately not every screen; that is how a snapshot suite rots into a wall of re-recordings nobody reads.

## The one place production code is reshaped for testability

`SyncEngineDelegate` ships a **default implementation** that wipes local data on both `.signOut` and `.switchAccounts`. ADR-0009 decided the opposite. If the app ever silently stops overriding it — a refactor, a protocol change on an untagged branch — it deletes every List the moment someone signs out of iCloud. That is the most destructive failure available here, and it fails in the direction of the library's default.

It is also unreachable by a test: the method's first parameter is a live `SyncEngine`, so invoking it needs a CloudKit container and entitlements, and there is no protocol seam to fake.

So the policy is extracted into a pure `shouldDeleteLocalData(on:) -> Bool` in `Database`, with the delegate method reduced to one line that calls it. **The bar for reshaping production code this way is set here: failures that destroy data.** Nothing else clears it — notably not ADR-0017's haptic.

## Consequences

`Models`, `Preferences`, `Acknowledgements`, `Components`, `ListDetailFeature`, `SettingsFeature`, `AppFeature` and `App` carry no tests. `SyncEngine` is never constructed in tests and no test target touches CloudKit: once the account-change policy is extracted there is no app-owned behaviour left in the sync path.

**Done means every rule in `CONTEXT.md` that falls inside the four targets' scope has at least one test whose name states it.** The rules list is already the checklist and is already maintained; a coverage percentage would be meaningless with five targets deliberately untested. It fails usefully in both directions — an unpaired rule is visible in seconds, and an unpaired test is a prompt to ask whether the rule was never written down or the test is not earning its place.

Two riders: a reference image is never re-recorded in the same commit as a behaviour change, and a new rule lands in `CONTEXT.md` before its test.
